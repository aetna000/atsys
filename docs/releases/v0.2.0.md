# AtSys 0.2.0

This release packages the local coding-task control plane, dashboard and Codex onboarding skill as a Python distribution. Give Codex an objective; it prepares a plan and independent acceptance checks, submits a managed task and verifies handoff to a separate worker.

## Install and start

```sh
python -m pip install --upgrade atsys==0.2.0
cd /path/to/your/git/repository
atsys init
```

Open or reopen Codex in the repository and say `$atsys` followed by your objective and constraints. `atsys ui` opens the dashboard. Codex CLI and its existing login must be available for model-backed work. Python 3.10+ is required; the package dependency supplies Node 24, and the wheel includes compiled web/backend assets. Project-specific development tools remain prerequisites for the tasks that use them.

## Behavior and compatibility

Managed work has persisted task/attempt state, heartbeats, deadlines, bounded retries, separate supervisor diagnosis and optional policy-authorized repair, plus independent result validation. Task configuration and evidence are visible in the dashboard. Telegram notifications are opt-in.

Installation keeps runtime state outside site-packages in `~/.local/share/atsys` (or `ATSYS_DATA_DIR`). Project initialization preserves unrelated source, instructions, Git hooks and credentials. Source-development state in `.atsys` is not automatically migrated. Set `ATSYS_DATA_DIR` explicitly to reuse an existing compatible data store.

The existing repository Apache-2.0 license and reused component/font notices are retained. The separate `claude-atsys` implementation is not modified or migrated by this release.

## Limits and validation

The built-in OS watchdog service supports macOS; Linux requires its own service manager for automatic watchdog restart. Windows supervision is unsupported. This is a single-user local application. Tasks stop executing while the host sleeps or is powered off. Native session resume, enforced monetary budgets, distributed execution and team authentication remain future work.

Local acceptance covered 31 runtime tests, 18 desktop/mobile browser tests and five installed-wheel checks, including killing the macOS watchdog and observing OS restart. An additional regression check covers exited zombie processes so successful Linux tasks do not incorrectly escalate during process cleanup. The release workflow `workflows.yml` additionally gates registry publication on application/browser tests, building the wheel from its source distribution, metadata checks and installed-wheel checks on Linux. Publication uses GitHub OIDC Trusted Publishing; it does not use the local API token.
