# AtSys 0.2.1

More reliable goal monitoring and recovery, with a readable terminal and dashboard.

## Install or upgrade

```sh
python -m pip install --upgrade atsys==0.2.1
# Or, for an isolated command installation:
uv tool install --upgrade atsys==0.2.1
cd /path/to/your/git/repository
atsys init
atsys ui
```

Wait for active tasks to finish or explicitly stop them before replacing the Python
environment that owns their runners/service. Keep the same `ATSYS_DATA_DIR` to retain
history. On macOS, rerun `atsys service install` after upgrading so the watchdog uses
the new installation; restart the dashboard to load its refreshed UI. No history or
project-data deletion is needed. Existing task configurations retain their explicit
monitoring/permission settings; inspect and update an old task rather than assuming
the new defaults were retroactively applied. `atsys init` preserves customized skill
files instead of silently replacing them.

## Changes

- Setup doctor during initialization and before worker execution; explicit
  `atsys doctor --config .atsys/tasks/task.json`. Validates configuration, required
  executables, workspace access, setup disk reserve and a private write/read pilot.
- New Codex tasks default to task-unique milestone monitoring. The observer detects
  a progress stall even if the worker is alive and producing output.
- Supervisor and repair roles receive the complete plan, acceptance contract,
  permissions and remaining limits. Approved recovery instructions reach the next
  worker; empty command arrays remain valid for objective-driven Codex tasks.
- Evidence-backed blocker reports and bounded follow-up diagnosis, safer explicit
  retry reconciliation, and process-cleanup race handling.
- Readable `atsys task status ID`, `atsys task watch ID` and `atsys task logs ID`.
  Watch is read-only; closing it leaves managed execution running. Full JSON remains
  available through `task show`, `status --json` and `logs --raw`.
- Dashboard prioritizes current progress, observer findings, active supervisor/repair
  phase and next action. Preserves checkpoint visibility during recovery and flushes
  final worker progress before validation. Verbose configuration/output is expandable.
- Installed dashboard deep links work beneath hidden installation directories;
  quick restarts no longer mistake TIME_WAIT for an occupied dashboard port.
- Package, health endpoint and dashboard version labels agree.

## Compatibility and validation

Python 3.10+; bundled Node 24 and dashboard. Codex CLI and its login remain external
prerequisites for model-backed roles. macOS has built-in LaunchAgent protection;
Linux requires its own service manager for watchdog restart protection. Windows
supervision remains unsupported. No database migration or AtMem dependency is added.

Local gates passed 47 runtime/API/CLI tests, 18 desktop/mobile browser tests and six
clean installed-wheel tests on macOS. See [candidate verification](v0.2.1-verification.json).
The release is additionally gated on runtime/API/CLI tests, desktop/mobile browser checks, clean
installed-wheel tests, type checking, formatting, application build and package
metadata checks. Native controlled recovery tests injected a persistent configuration
fault after task 5/20, observed read-only diagnosis and separately authorized repair,
then resumed without replay and independently validated twenty unique results.
See [the detailed review](../USABILITY-20261024.md). These are controlled local
supervision tests, not DolphinBench accuracy results.

Generic commands execute as the local user, not in a sandbox. Codex networking is
explicit opt-in. Observers inspect, supervisors propose, policy authorizes and an
independent validator establishes completion. Unknown costs remain unknown. Sleeping
or powered-off hosts cannot make progress. Bounded recovery does not guarantee that
an arbitrary goal is achievable.
