# AtSys 0.3.0

This stable release promotes the 0.3.0b4 provider-parity beta. Install or upgrade:

```sh
python -m pip install --upgrade atsys==0.3.0
```

GitHub Copilot CLI and Claude Code can now fill worker, read-only supervisor and
bounded repair roles alongside Codex. Select providers independently in the web
UI, task JSON or template flags. Supervisor inherits the coding worker unless
selected explicitly; repair inherits supervisor. There is no silent fallback.

```sh
atsys providers
atsys init --provider copilot
atsys integrate --provider claude
atsys task template --worker copilot --objective "Implement my feature" \
  --output .atsys/tasks/feature.json
```

Each provider gets its own project skill; installation and removal preserve other
skills and local edits. Goals, independent validators, reports, deadlines,
recovery budgets and process controls share the durable AtSys watchdog. Terminal
activity formats native provider messages and tool calls.

Portable `agent_*` callbacks adapt to supported native tool, turn, session and
compaction events. Existing `codex_*` hooks remain compatible. Hook identity and
completion receipts are bound to the actual attempt/provider. Large callback
contexts are redacted as structured data without truncating JSON. Copilot's
native Node launcher retains the user's system Node, and automatic model routing
keeps its native reasoning defaults. Goal prompts require literal milestone
names and planSource values instead of inviting agents to paraphrase them.

## Permissions and upgrade

Install each native CLI and sign in using its normal workflow. `atsys providers`
checks executable presence, not account access. Copilot/Claude worker and repair
tools run as the local user and require `trustedLocalExecution:true`; this is not
Codex's OS sandbox. Supervisors expose read/search tools only. See
[provider setup and capability limits](../PROVIDERS.md).

Codex native hooks retain normal `/hooks` trust review. A configured native bridge
that never connects fails the attempt and cannot proceed to validation. Lifecycle
hooks do not require provider-native trust. Copilot has no post-compaction event
or universally blocking before-turn hook. Turn callbacks do not intercept every
internal model HTTP request. AtSys process pause does not pause remote requests
or resume a provider's native session.

Restart an explicitly owned, idle watchdog with the upgraded package before using
new provider settings or portable hooks. Older watchdogs are rejected for these
configurations. Do not replace active runners or another AtSys instance. Existing
Codex/command tasks and legacy role inheritance remain supported.

## Verification and limits

The live acceptance evidence below was recorded for 0.3.0b4; it is not a new long-duration stable-version trial. Version metadata changes mean the release artifacts are not byte-identical.

On 30 October, the initial backend run under concurrent browser/build load failed
one timing-sensitive hook-progress assertion (98/99); the full suite passed
99/99 when rerun without concurrent checks. This is a timing sensitivity, not
proof of its cause. The stable candidate passed 20 desktop/mobile browser checks.

The beta qualification recorded: 99 backend tests, production/runtime build and formatting,
20 desktop/mobile browser tests, 24 installed-wheel installation/onboarding, hook
SDK and terminal checks, and two optional AtBot tests using Pydantic TestModel.
Wheel and source distribution metadata checks passed. Real isolated Copilot and Claude workers passed the same external Python
validator (11 input cases plus README existence), with durable reports, artifact
digests and native hook receipts. Real Codex acceptance and exact check totals
are recorded in the [verification log](../../specs/008-provider-parity/verification.md).
The tag workflow repeats Linux tests and publishes the tested distributions.

Live provider tests are short acceptance checks, not overnight reliability proof.
Copilot/Claude supervision, repair, retry and process controls have deterministic
fixture coverage; the small live tasks do not establish every recovery path.
Costs are unknown. Earlier live attempts remain recorded, including unavailable
models and hook trust failures. The first Copilot/Claude workers paraphrased
planSource, so their percentages were rejected; independent completion validation
passed. The beta tightened the prompt while retaining strict progress validation.
Windows supervision remains unsupported; Linux requires separate OS service
configuration for watchdog restart protection. Notifications remain opt-in.
