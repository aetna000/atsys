# AtSys 0.3.0b1

Beta release with lifecycle/native Codex hooks and a focused operational UI.

Install with `python -m pip install --upgrade atsys==0.3.0b1`. After upgrading, restart the watchdog using the upgraded runtime; see [upgrade instructions](../HOOKS.md#upgrading-the-watchdog).

Adds opt-in task lifecycle callbacks, quiet-work progress observations, durable bounded callback runners/receipts, before-run/validation gates, a sync/async Python decorator SDK, and dashboard configuration/results. Hook tasks require an upgraded watchdog rather than silently executing on an older daemon.

Native Codex integration observes pre/post tool calls and model turn boundaries with reported model metadata. Pre-tool handlers can deny supported operations. Project installation preserves unrelated hooks and requires normal Codex `/hooks` trust review. Internal model HTTP requests and some tool paths are outside native coverage. The optional `atsys[atbot]` adapter reuses AtBot's Pydantic AI provider and actual model-request capability hooks without making observers task authorities.

Independent validation, recovery permissions, retry limits and deadlines retain authority. Hook commands are trusted local code; native hooks are guardrails, not complete isolation. See [usage and limits](../HOOKS.md) and [native Codex verification](../native-hooks-verification.json).

The product UI now exposes working managed-task and service/Telegram controls. Sample fleet/costs/approvals and unavailable companion pages are removed from navigation/routes. Readable activity includes all attempts, decodes JSON/tool envelopes, preserves multiline messages, and shows newest entries first with text/attempt filters and a pause-display control. CLI logs include all phases; the read-only monitor places latest activity near the top and refreshes for real output changes. Raw output remains explicitly available.
