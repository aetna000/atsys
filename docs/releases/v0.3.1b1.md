# AtSys 0.3.1b1 — model capacity recovery beta

This opt-in beta adds bounded fallback when a managed Codex, Claude Code or
GitHub Copilot worker reports a recognized model-capacity failure. AtSys records
the failure, confirms process cleanup, and schedules a new attempt with the next
explicitly approved model of the **same provider**. It preserves workspace and
attempt evidence and still requires independent validation for completion.

## Install or upgrade

```sh
python -m pip install --upgrade atsys==0.3.1b1
atsys --version
```

Stable users can remain on `0.3.0`. The package requires Python 3.10+ and supports
managed supervision on macOS and Linux; Windows supervision is unsupported.
Restart an explicitly owned, idle watchdog using the upgraded package before
submitting or changing a task that enables fallback. Do not replace an active
runner or another owner's service. Existing configurations remain valid and do
not enable fallback automatically.

## Opt-in configuration

Set these fields in the managed task JSON, alongside the existing objective,
workspace, validator and other required task fields:

```json
{
  "worker": "codex",
  "model": "your-primary-model-id",
  "capacityFallbackModels": ["your-approved-fallback-model-id"],
  "recovery": "supervised",
  "maxRetries": 2,
  "backoffSeconds": 30
}
```

For Claude or Copilot, set `worker` to `claude` or `copilot` and use model IDs
available to that provider and account. Their worker requires the existing
`trustedLocalExecution` authorization. IDs above are placeholders, not suggested
model names. Use the provider's model-listing interface to choose your models.
Retries, deadline and fallback list are bounded; once exhausted, the task needs
operator attention. The task retains its original configured model; each attempt
and model switch is recorded. Recognized capacity recovery uses deterministic
policy without requiring a model-based supervisor diagnosis.

## Limits and compatibility

This covers structured provider error signals described in
[the provider guide](../PROVIDERS.md). Generic rate limits, quota exhaustion and
authentication failures are not treated as model-capacity failures. Real provider
capacity responses and their formats have **not** been independently captured or
validated for this beta; recognition may miss them. It does not intercept an
independently launched interactive session or guarantee service availability.
It does not fall back across providers. An indefinitely running CLI still depends
on configured stall/deadline detection.

Fallback starts a **new attempt**, not a native session resume. Prior task evidence
and the workspace are retained, but in-memory conversation state is not promised.
Automatic replay can repeat external side effects; enable it only for tasks where
recovery is authorized and effects can be reconciled. Fallback models may differ
in behavior, cost, permissions or availability; configure only acceptable models.
No extra model calls were made to validate capacity recovery.

## Verification

The implementation was exercised with simulated provider CLI errors and real
managed processes, bounded retries, watchdog compatibility checks, and separate
validators. These fixture results are not evidence of live provider capacity or
long-duration resilience. The release workflow independently tests the tagged
Linux artifacts and publishes only on success.
