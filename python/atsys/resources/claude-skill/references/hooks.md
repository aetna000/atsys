# Project and native agent hooks

Use hooks only when the task needs them. `atsys hooks events` lists supported events; `atsys task schema` gives the installed definition schema. A definition contains `id`, `events`, `argv`, optional `phases`, `timeoutSeconds`, `intervalSeconds`, `maxInvocations`, `failurePolicy` (`fail` or `continue`), and optional native tool `matcher` regex.

Python handlers use `from atsys.hooks import Hooks, HookResult`, `hooks = Hooks()`, and decorators such as `@hooks.on.on_tick` or `@hooks.on.agent_pre_tool`. Execute them with argv `["atsys", "hooks", "run", "project_hooks.py:hooks"]` or an absolute installed Python interpreter followed by `-m atsys.hooks run project_hooks.py:hooks`. Context arrives on stdin; stdout is a single result JSON object. Diagnostic SDK prints go to stderr.

`before_run` and `before_validation` gate process launch. `on_tick` observes long quiet work. Other task events observe successful/failed runs, recovery and terminal outcomes. Return `message`, `decision` (`continue`, `fail`, `escalate`), or real `progress` (`completed`, `total`, optional `checkpoint`). Hooks cannot grant repair, increase retries, change deadlines or mark completion. Custom domain progress must use a consistent total; if replacing Claude Code's automatic milestone file, set `goalMonitoring: false`, configure `on_tick`, and choose a meaningful `progressTimeoutSeconds`. Set `activityTimeoutSeconds: 0` for legitimately silent work. Repeated identical progress cannot keep a stalled task alive.

Native Claude Code events include `agent_pre_tool`, `agent_post_tool`, `agent_before_model_turn`, `agent_after_model_turn`, `agent_session_start`, `agent_pre_compact`, and `agent_post_compact`. `ctx.native` carries reported model/session/tool metadata and tool input/result when available. Pre-tool `decision: fail` denies a supported tool call. Post-tool callbacks cannot undo execution. Turn boundaries do not intercept every internal model HTTP request; some hosted/specialized tools are outside native coverage.

AtSys injects native bridge configuration per attempt; do not modify global or project hook settings. A missing bridge handshake fails coverage instead of claiming hooks ran. Copilot has no post-compaction callback; before-turn/session-start/pre-compaction callbacks must use failurePolicy=continue. Hook denials fence managed execution; provider callbacks are not OS security boundaries.

Ordinary callbacks need no model. Optional `atsys[atbot]` supplies `atsys hooks atbot --config /repo/atbot.json --provider NAME`, using AtBot's Pydantic AI provider and configured capabilities, including real per-model-request hooks. Remote observation requires both configured remote egress and `--allow-remote`; do not broaden the user's authorization.

Inspect `task show` for callback receipts and the dashboard for configuration/results. Callback deliveries have bounded time and counts; interrupted uncertain deliveries are not automatically replayed. Use invocation IDs to deduplicate external effects. Hook tasks require a healthy upgraded watchdog; report an upgrade rejection rather than dropping hook configuration.

Copilot/Claude worker and repair shell tools require explicit trustedLocalExecution:true (template --trusted-local-execution) within the user-authorized local coding scope. Never imply this is Codex sandbox containment or an OS network denial. Preserve this constraint in the goal contract; if incompatible, select Codex rather than weakening it. Supervisor and repair providers may be selected independently.
