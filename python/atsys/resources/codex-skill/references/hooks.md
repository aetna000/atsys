# Project and native agent hooks

Use hooks only when the task needs them. `atsys hooks events` lists supported events; `atsys task schema` gives the installed definition schema. A definition contains `id`, `events`, `argv`, optional `phases`, `timeoutSeconds`, `intervalSeconds`, `maxInvocations`, `failurePolicy` (`fail` or `continue`), and optional native tool `matcher` regex.

Python handlers use `from atsys.hooks import Hooks, HookResult`, `hooks = Hooks()`, and decorators such as `@hooks.on.on_tick` or `@hooks.on.codex_pre_tool`. Execute them with argv `["atsys", "hooks", "run", "project_hooks.py:hooks"]` or an absolute installed Python interpreter followed by `-m atsys.hooks run project_hooks.py:hooks`. Context arrives on stdin; stdout is a single result JSON object. Diagnostic SDK prints go to stderr.

`before_run` and `before_validation` gate process launch. `on_tick` observes long quiet work. Other task events observe successful/failed runs, recovery and terminal outcomes. Return `message`, `decision` (`continue`, `fail`, `escalate`), or real `progress` (`completed`, `total`, optional `checkpoint`). Hooks cannot grant repair, increase retries, change deadlines or mark completion. Custom domain progress must use a consistent total; if replacing Codex's automatic milestone file, set `goalMonitoring: false`, configure `on_tick`, and choose a meaningful `progressTimeoutSeconds`. Set `activityTimeoutSeconds: 0` for legitimately silent work. Repeated identical progress cannot keep a stalled task alive.

Native Codex events include `codex_pre_tool`, `codex_post_tool`, `codex_before_model_turn`, `codex_after_model_turn`, `codex_session_start`, `codex_pre_compact`, and `codex_post_compact`. `ctx.native` carries reported model/session/tool metadata and tool input/result when available. Pre-tool `decision: fail` denies a supported tool call. Post-tool callbacks cannot undo execution. Turn boundaries do not intercept every internal model HTTP request; some hosted/specialized tools are outside native coverage.

Before native use, run `atsys hooks codex-install --config TASK.json --project /repo`, then review the generated definitions in the project's Codex `/hooks` interface. Do not bypass trust or modify unrelated definitions. The installer merges existing `.codex/hooks.json` and refuses to overwrite local modifications. Missing bridge handshake prevents a successful Codex exit from claiming hook coverage, but native hooks are not a complete security boundary.

Ordinary callbacks need no model. Optional `atsys[atbot]` supplies `atsys hooks atbot --config /repo/atbot.json --provider NAME`, using AtBot's Pydantic AI provider and configured capabilities, including real per-model-request hooks. Remote observation requires both configured remote egress and `--allow-remote`; do not broaden the user's authorization.

Inspect `task show` for callback receipts and the dashboard for configuration/results. Callback deliveries have bounded time and counts; interrupted uncertain deliveries are not automatically replayed. Use invocation IDs to deduplicate external effects. Hook tasks require a healthy upgraded watchdog; report an upgrade rejection rather than dropping hook configuration.

Portable agent_pre_tool, agent_post_tool, agent_before_model_turn, agent_after_model_turn, agent_session_start, agent_pre_compact and agent_post_compact work across supported adapters. Copilot has no post-compaction callback and before-turn/session/pre-compaction hooks are observation-only (failurePolicy:continue). Per-attempt Claude settings and Copilot plugin hooks are injected without editing user/project configuration. Legacy codex_* events remain Codex-specific. No native callback is a per-HTTP model interceptor.
